## Key File Locations

**Entry Points:**

| File | Purpose | URL | Auth Required |
|------|---------|-----|---|
| `index.php` | User-facing booking interface | `/` or `/?action=...` | No (login available) |
| `admin.php` | Admin management interface | `/admin.php?action=...` | Yes (separate login) |

**Configuration:**
- `conf.php`: Database connection string and credentials - imported by both entry points at top
- `.htaccess`: Denies direct access to `conf.php` and `pg.sql` to protect credentials

**Core Logic:**

All application logic lives directly in entry point files:
- `index.php`: User interface (lines 1-14 headers, 19-30 helpers, 31-237 auth, 245-644 operations, 646-705 data loading, 710-970 rendering)
- `admin.php`: Admin interface (lines 1-19 headers, 19-30 helpers, 31-83 bootstrap, 141-349 operations, 356-735 routing and rendering)

**Database:**
- `pg.sql`: Complete PostgreSQL schema including:
  - Table definitions (app_user, court, booking, recurring_series, recurring_exception)
  - Indexes for performance (booking_time_idx uses GIST for range queries)
  - Trigger function prevent_overlap() for conflict detection
  - Stored functions: create_booking(), free_courts(), prune_old()

## Naming Conventions

**PHP Files:**
- Pattern: lowercase.php
- Examples: `index.php`, `admin.php`, `conf.php`

**Database Objects (PostgreSQL):**
- Schema: `book_courts` (all objects scoped here)
- Tables: snake_case (app_user, booking, court, recurring_series, recurring_exception)
- Functions: snake_case (prevent_overlap, create_booking, free_courts, prune_old)
- Types: snake_case (user_role, booking_source, booking_status)
- Indexes: object_shortname_idx (booking_time_idx)

**Variables/Parameters (PHP):**
- Local variables: camelCase ($bookDate, $courtName, $isAdmin)
- DB parameters: snake_case with colon prefix (:p_user_id, :court_id, :start_date)
- Session keys: lowercase ($\_SESSION['user'], $\_SESSION['csrf'], $\_SESSION['flash'])
- GET/POST keys: snake_case ($_GET['action'], $_POST['duration_min'], $_POST['series_id'])

**Functions (PHP):**
- Helpers: snake_case (pdo(), csrf_token(), is_logged_in(), render_time_select())
- Actions (POST handlers): naming pattern = "action" (create_booking, cancel_series, user_create)

**HTML/CSS:**
- Classes: Tailwind CSS utility classes (p-4, rounded-xl, bg-indigo-600)
- IDs: camelCase (freeCourtsWrap, cancelDialog, weekDateInput)
- Form inputs: snake_case (start_time, duration_min, book_date)

**Database IDs:**
- Pattern: UUID columns (UUID PRIMARY KEY DEFAULT gen_random_uuid())
- When used in URLs/forms: cast to text and pass as string

## Where to Add New Code

**New User Feature (e.g., new booking form field):**
- Form markup: `index.php` in the "Neue Buchung" details section (around line 862-906)
- Form validation: `index.php` in `create_booking` POST handler (lines 424-466)
- Database changes: Add column to `booking` table in `pg.sql`, update `create_booking()` function if needed
- Display logic: Update day view rendering (lines 827-849)

**New Admin Operation (e.g., export bookings):**
- Route handling: Add new action check in `admin.php` POST section (around line 241-349)
- Page rendering: Add new case in switch statement (lines 356-733)
- Helper function: Add to `admin.php` above switch statement if needed

**New API Endpoint (e.g., list bookings for user):**
- Location: Add near existing AJAX endpoints in `index.php` (after line 401)
- Pattern: Check for `action` parameter, set `Content-Type: application/json`, output JSON, exit
- Example: `if (($_GET['action'] ?? '') === 'my_bookings') { ... json_encode(...) ... exit; }`

**New Database Function (complex query):**
- Location: Add to `pg.sql` after existing functions (after line 279)
- Pattern: Use `CREATE OR REPLACE FUNCTION` with schema-qualified names
- Call from PHP: Prepare and execute via PDO

**New Helper Function:**
- PHP helpers: Add near top of each file (after pdo() function, around line 30-100)
- Database functions: Add to pg.sql with CREATE OR REPLACE FUNCTION

**Utilities/Shared Code:**
- Current pattern: Duplicated between `index.php` and `admin.php` (pdo(), h(), csrf_token())
- Future refactor: Consider extracting to separate `helpers.php` file

## Database Schema Quick Reference

| Table | Purpose | Key Fields |
|-------|---------|-----------|
| `app_user` | Users and admins | id, email, password_hash, full_name, role, is_active |
| `court` | Tennis courts | id, name, location, is_active |
| `booking` | Individual reservations | id, user_id, court_id, time_span (TSTZRANGE), status, source, series_id, title |
| `recurring_series` | Recurring booking templates | id, user_id, court_id, weekday, start_time, duration_min, start_date, end_date, is_active |
| `recurring_exception` | Exceptions to recurring series | id, series_id, occur_date, canceled |

## How Dependencies Work

- **index.php imports:** conf.php (line 14)
- **admin.php imports:** conf.php (line 14)
- **Database:** PostgreSQL with schema book_courts (required)
- **No external PHP packages:** Everything is vanilla PHP + PDO

## Deployment Structure

When deploying:
1. Copy `index.php`, `admin.php`, `conf.php` to web root
2. Copy `.htaccess` to web root to protect config files
3. Update database credentials in `conf.php`
4. Create PostgreSQL database and run `pg.sql` to initialize schema
5. Make `conf.php` non-world-readable for security
