Create `config.php` in the project root (sibling to `conf.php`, NOT in a new subdirectory — this app is intentionally flat, and CONTEXT.md is explicit that introducing a structural change like a config object/class or new directory layer is out of scope for this phase). Content:

```php
<?php
declare(strict_types=1);

/**
 * Load .env configuration and populate global DB config variables.
 *
 * Replaces conf.php. Must be required before any pdo()/database call.
 *
 * @throws RuntimeException if .env is missing, unreadable, or missing required keys
 */
function load_env_config(): void
{
    $env_file = __DIR__ . '/.env';

    if (!file_exists($env_file)) {
        throw new RuntimeException(
            "Configuration file not found: {$env_file}\n" .
            "Copy .env.example to .env, fill in real values, then run: chmod 600 .env"
        );
    }

    $config = parse_ini_file($env_file, false, INI_SCANNER_NORMAL);
    if ($config === false) {
        throw new RuntimeException("Failed to parse .env file at {$env_file}");
    }

    $required = ['DB_HOST', 'DB_PORT', 'DB_NAME', 'DB_USER', 'DB_PASS'];
    foreach ($required as $key) {
        if (!array_key_exists($key, $config) || $config[$key] === '') {
            throw new RuntimeException("Missing or empty configuration key in .env: {$key}");
        }
    }

    global $DB_HOST, $DB_PORT, $DB_NAME, $DB_USER, $DB_PASS, $dsn;
    $DB_HOST = (string) $config['DB_HOST'];
    $DB_PORT = (string) $config['DB_PORT'];
    $DB_NAME = (string) $config['DB_NAME'];
    $DB_USER = (string) $config['DB_USER'];
    $DB_PASS = (string) $config['DB_PASS'];

    $dsn = "pgsql:host={$DB_HOST};port={$DB_PORT};dbname={$DB_NAME};options='--client_encoding=UTF8'";
}

load_env_config();
```

Create `.env` in the project root by migrating the CURRENT real values out of `conf.php` programmatically. Do NOT retype or paste the password by hand — extract it via a PHP one-liner so it is never displayed in a terminal transcript, written into a plan file, or pasted into chat. Run this exact command from the project root (it reads `conf.php`, writes `.env`, and quotes any value that would otherwise break INI parsing):

```bash
php -r '
require "conf.php";
$esc = static function (string $v): string {
    return preg_match("/[;\"\x27\\\\#\s]|[^\x00-\x7F]/", $v) ? "\"" . $v . "\"" : $v;
};
$lines = [
    "DB_HOST=" . $esc($DB_HOST),
    "DB_PORT=" . $esc((string)$DB_PORT),
    "DB_NAME=" . $esc($DB_NAME),
    "DB_USER=" . $esc($DB_USER),
    "DB_PASS=" . $esc($DB_PASS),
];
file_put_contents(".env", implode("\n", $lines) . "\n");
'
chmod 600 .env
```

The `$esc` closure double-quotes any value containing `;`, quotes, backslashes, whitespace, or non-ASCII bytes. The current `DB_PASS` contains both a `;` and a non-ASCII character, so it WILL be quoted by this command. This matters because `parse_ini_file()` truncates an UNQUOTED value at the first unescaped `;` (INI comment marker) — without quoting, the migrated password would be silently corrupted to everything before the first `;`.
