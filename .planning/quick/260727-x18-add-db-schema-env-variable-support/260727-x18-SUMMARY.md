# Quick Task 260727-x18: Add DB_SCHEMA Environment Variable Support Summary

**PostgreSQL schema name centralized into DB_SCHEMA env var, consumed by explicit SET search_path in both PDO connections and a default-compatible psql variable in pg.sql.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 3 completed
- **Files modified:** 6 (config.php, .env, .env.example, index.php, admin.php, pg.sql)

## Accomplishments
- `config.php` now requires and loads `DB_SCHEMA` into `global $DB_SCHEMA`, following the exact same required-key/global-assignment pattern as the existing 5 `DB_*` keys.
- `index.php` and `admin.php`'s `pdo()` functions each execute `SET search_path TO "<schema>"` exactly once per new connection (inside the `if ($pdo === null)` block), replacing implicit reliance on the DB role's default search_path.
- `pg.sql` no longer hardcodes `book_courts` in its `DROP SCHEMA`, `CREATE SCHEMA`, or two `SET search_path` statements — all four now use a `:"schema_name"` psql variable defaulting to `book_courts` via `\set schema_name book_courts`, overridable at invocation time with `psql -v schema_name=other_name -f pg.sql`. All other `book_courts.*` qualified references (~20 occurrences across table/function names) were left untouched.

## Task Commits

Each task was committed atomically:

1. **Task 1: Add DB_SCHEMA to config.php, .env, and .env.example** - `870f598` (feat)
2. **Task 2: Set search_path in index.php and admin.php pdo() functions** - `2aa847e` (feat)
3. **Task 3: Replace hardcoded book_courts schema name in pg.sql with a psql variable** - `005d52b` (feat)

_Note: `.env` was also updated (real `DB_SCHEMA=book_courts` value) as part of Task 1, but `.env` is gitignored and therefore not committed — verified via `git check-ignore .env`._

## Files Created/Modified
- `config.php` - `DB_SCHEMA` added to `$required` validation array and to `global $DB_SCHEMA` assignment in `load_env_config()`
- `.env` - Added `DB_SCHEMA=book_courts` (real, gitignored, not committed)
- `.env.example` - Added empty `DB_SCHEMA=` template line
- `index.php` - `pdo()` adds `$DB_SCHEMA` to its `global` declaration and calls `$pdo->exec('SET search_path TO "' . $DB_SCHEMA . '"')` once per new connection
- `admin.php` - Same change as `index.php`, 4-space indent
- `pg.sql` - Added `\set schema_name book_courts` as the first line; replaced the literal `book_courts` in `DROP SCHEMA`, `CREATE SCHEMA`, and both `SET search_path` statements with `:"schema_name"`

## Decisions Made
- Schema name is applied via a dedicated `SET search_path` exec after connection, not folded into the DSN — keeps the DSN construction in `config.php` unchanged and mirrors how PostgreSQL treats search_path as a session-level setting rather than a connection parameter.
- Used double-quoted identifier substitution consistently: PHP-side `'SET search_path TO "' . $DB_SCHEMA . '"'` and psql-side `:"schema_name"` — both produce a safely quoted SQL identifier regardless of case sensitivity.
